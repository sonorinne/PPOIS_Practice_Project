# Графический интерфейс «Своя игра»

Qt Quick / QML + C++17. Работа ведётся в `feature-gui`, основа — `feature-core_logic`.
На момент ответвления `feature-core_logic` и `feature-statistics` совпадали (`b5bbb16`).

## Запуск

Установите CMake 3.21+, компилятор C++17 и Qt **6.5+** с модулями Qt Quick,
Quick Controls 2, Qt Multimedia и Qt Test. Рекомендуется Qt 6.8.3.
Проще всего открыть `CMakeLists.txt` в Qt Creator, выбрать Desktop kit и добавить
CMake-параметр `OWNGAME_BUILD_GUI=ON`, затем выбрать цель **OwnGameGui**.
На Windows используйте Qt kit для того же компилятора, которым собирается проект
(например, MSVC 2022 x64). На Linux также нужны заголовки OpenGL и зависимости Qt.

Из терминала (путь замените на установленный Qt):

```bash
cmake -S . -B build-gui -DOWNGAME_BUILD_GUI=ON -DCMAKE_BUILD_TYPE=Debug -DCMAKE_PREFIX_PATH="/path/to/Qt/6.8.3/gcc_64"
cmake --build build-gui --config Debug --parallel
ctest --test-dir build-gui -C Debug --output-on-failure
```

Запуск: `build-gui/OwnGameGui` (Linux) или `build-gui/Debug/OwnGameGui.exe` (Windows/MSVC).
Из Qt Creator запуск автоматически получает окружение Qt. При запуске Windows-приложения
вне Qt Creator выполните `windeployqt --qmldir gui/qml build-gui/Debug/OwnGameGui.exe`
из терминала соответствующего Qt kit. Папка `assets` должна лежать рядом с exe;
CMake копирует её при сборке. Для передачи приложения другому компьютеру нужна вся
папка с Qt-библиотеками, плагинами и assets, а не только exe.

Без `OWNGAME_BUILD_GUI=ON` проект собирается как прежде, Qt не требуется.
Для smoke-проверки запуска есть аргумент `--smoke-test` (автовыход через 1.5 секунды).

## Управление и режимы

- Введите имя, выберите табло или тренировку.
- Табло: шесть тем × пять стоимостей; выбор мышью или Tab → Enter/Space.
  После выбора тема и стоимость подсвечиваются; использованная стоимость исчезает.
- Ответ: поле ввода, Enter или «Ответить». «Показать ответ» не снимает баллы; в тренировке увеличивает счётчик ошибок.
  Проверка использует эталон и альтернативы из базы, с пробелами по краям и вариантами регистра.
  Свободные перефразировки автоматически не распознаются.
- В классическом режиме верный ответ прибавляет стоимость, ошибка вычитает.
- В тренировке нет штрафа; можно выбрать несколько тем, диапазон стоимости и длину.
  Пустой выбор тем означает смешанную тренировку. Количество ограничено доступной базой.
  После завершения можно повторить только ошибки.
- Музыкальный вопрос: вращающийся скрипичный ключ, текст под ним, пауза и повтор.
  Аудио останавливается при ответе и выходе. Для изображения текст также расположен снизу.
- «Кот в мешке»: скрывается в случайной ячейке, открывает новую случайную тему,
  после чего игрок выбирает 100 или 500. В каждом раунде три таких вопроса. Выбранная стоимость определяет вопрос и ставку.
- Для следующего табло нужно закончить все 30 ячеек. Темы выбираются без возвращения;
  тема кота также исключается. Для нового раунда нужны девять новых полных тем: шесть для табло и три для котов. Иначе сессия заканчивается.
  Количество раундов определяется числом полных тем в базе; неиспользованный остаток не повторяется.
- «Завершить сессию» сохраняет отвеченные вопросы. Незавершённый вопрос не учитывается.
- Архив хранит до 50 результатов локально через QSettings, отдельно от базы вопросов.
  История сохраняется при штатном завершении сессии; восстановление после аварийного закрытия не реализовано.
- Переключатель «Эфир / CRT» отключает шум, полосы развёртки, вращение и декоративное движение.

## Архитектура

`BoardSession` — чистый C++: колода полных тем, формирование табло, использованные ячейки,
выбор специального вопроса. Никаких Qt-зависимостей.
`CatQuestion : IQuestion` — полиморфная обёртка; сохраняет исходный вопрос, альтернативы
и медиа, но задаёт выбранную стоимость. Остальные типы вопросов и шаблонный `DataManager<T>` сохранены.
`GameController` связывает существующие `Game`, `TrainingSession`, `Statistics` и базу
с QML. Вопросы GUI загружаются в SQLite `:memory:`, история хранится отдельно:
`QSettings("OwnGameStudentProject", "OwnGameGui")` (реестр Windows / конфигурация Linux/macOS).
`gui/qml` содержит экраны и оригинальный векторный low-poly кот в академической шапочке.
Шрифт Oswald распространяется по SIL OFL, текст лицензии находится рядом в `gui/assets`.
Графика кота и фоны рисуются программно, кадры телепередачи не встраиваются.

## Проверки

`UnitTests` включает существующие тесты и проверки новых правил: шесть полных тем,
отсутствие повторов вместе с темой кота, запрет повторного выбора, допустимые ставки,
истощение колоды, сброс сессии и делегирование альтернативных ответов.
`GuiTests` проверяет начисление, сохранение истории, тренировку и повтор ошибок, загрузку QML,
выбор мышью и оба медиаформата. В headless CI используется offscreen/software рендеринг.
Для снимков экранов при запуске `GuiTests` задайте `OWNGAME_SCREENSHOT_DIR`.
Проверка фактического звука требует устройства вывода; headless среда проверяет загрузку и декодирование.
GitHub Actions дополнен отдельной Qt-сборкой Linux; существующая Windows-проверка сохраняется.

## Как перенести изменения и отправить ветку

Если вы получили `feature-gui.patch`, откройте терминал в свежем клоне репозитория
и выполните (при существующей локальной `feature-gui` просто переключитесь на неё):

```bash
git fetch origin
git switch -c feature-gui origin/feature-core_logic
git apply --index /path/to/feature-gui.patch
git diff --cached --stat
# Соберите проект и запустите тесты, как описано выше.
git commit -m "Add retro Qt GUI, single-player board and cat questions"
git push -u origin feature-gui
```

На GitHub: **Compare & pull request** → base `feature-core_logic`, compare `feature-gui`.
Если команда решит интегрировать через `feature-statistics`, выберите её как base.
Не загружайте папки сборки и не заменяйте файлы вручную через веб-интерфейс.
Если основа ветки успела измениться и patch не применяется, сначала используйте
коммит `b5bbb16` как основу, примените patch, а затем интегрируйте изменения команды через merge.

## Обновление интерфейса
Настройки открываются отдельным окном: музыка, звуки, громкости и помехи сохраняются локально.
Пользовательская фоновая MP3 приглушается до нуля во время музыкального вопроса.
Звуки открытия, верного и неверного ответа синтезированы специально для проекта в стиле телевикторины.
Используется Oswald с кириллицей (SIL OFL), а не точная копия шрифта передачи.

## Меню, выбор тем и выход
Меню использует однострочный заголовок и вертикальные кнопки. Темы тренировки выбираются
в прокручиваемом списке; «Случайные темы» очищает ручной выбор и включает смешанный набор.
Кнопка «Выйти» завершает приложение; во время сессии требуется подтверждение, отвеченные
вопросы сохраняются в архиве. Закрытие окна крестиком использует такое же подтверждение.
Полная фоновая запись проигрывается с начала при запуске, зациклена и не перезапускается
при смене экранов; в аудиовопросах только приглушается.

## Звуки, автоматические раунды и ярлык
Фон: предоставленный `ost.MP3`. Сигналы сохранены из присланных записей:
`fanfare` — начало раунда, `time_outt` — завершение, `si2_cat` — кот,
`right` / `wrong` — проверка, `noanswer` — показ ответа (без сигнала ошибки).
При регулировке громкости звуков воспроизводится образец `right`.
После последнего вопроса нажмите «Продолжить»: следующий раунд начинается автоматически
после завершения сигнала (2.8 секунды). В начале появляется анимированная надпись в центре.
Кнопки диалогов и ползунок имеют отдельные цвета наведения.

### Ярлык на рабочем столе Windows
1. Соберите **OwnGameGui** в Qt Creator.
2. В папке проекта дважды нажмите **CreateShortcut.cmd**.
3. Скрипт найдёт exe в папке `build*`, при наличии CMakeCache найдёт соответствующий
   `windeployqt` и скопирует библиотеки Qt рядом с программой.
4. На рабочем столе появится «Своя игра» с иконкой кота.
Если exe собирался за пределами папки проекта, передайте путь:
`powershell -NoProfile -ExecutionPolicy Bypass -File .\CreateShortcut.ps1 -ExecutablePath "C:\path\OwnGameGui.exe"`.
Не удаляйте папку проекта после создания ярлыка: ярлык ссылается на exe и иконку в ней.
Иконка также встроена в Windows exe; PNG и ICO лежат в `gui/assets`.
Скрипт ярлыка и Windows-ресурс подготовлены для Windows; в облаке проверены сборка и GUI Linux.
